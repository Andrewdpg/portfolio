# Desk Room v2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn the 3D desk hero into a full-bleed, data-driven summary of Andrés: project posters, skill cubes, ICESI branding, a modeled avatar, a scroll-pinned camera tour, and the About section merged in.

**Architecture:** Pure logic (featured selection, icon sources, camera tour sampling) lives in small `.ts` modules under `src/features/desk/` with `node:test` tests and no new test dependency. Scene components in `DeskScene.tsx` consume that logic. `HomeSection` becomes a tall pinned section whose scroll progress drives `CameraRig`. The avatar is generated by a committed Blender `bpy` script into `public/models/avatar.glb` and loaded with three's `GLTFLoader` through r3f's `useLoader`.

**Tech Stack:** React 19, Vite 6, @react-three/fiber 9, three 0.187, Tailwind, Node 26 (`node --test`, native TS type stripping), Blender (dev-only, headless).

**Spec:** `docs/superpowers/specs/2026-11-01-desk-room-design.md`

## Global Constraints

- No hardcoded featured content in the scene: everything comes from `src/services/dataService.ts`.
- Featured projects: Waycairn, Methodus, Casia & Canela. About 12 featured skills, picked from Expert/Advanced skills with a real icon.
- Keep palette `C` in `DeskScene.tsx`, accent `#9B76D3`, the orthographic isometric camera, and the dark-only scene.
- Don't add `@react-three/drei` unless it clearly removes code. Default: three's own loaders plus `useLoader`.
- Keep: lazy scene import, `paused` → `frameloop="never"` when off-screen, CV download states, contact modal.
- Mobile (`max-width: 767px`) or `prefers-reduced-motion: reduce`: no camera tour, hero is 100dvh, static framed view, and posters and cubes stay tappable.
- Tests: `*.test.ts` next to the module, run with `npm test` (`node --test`). Test-imported modules must use only `import type` for local imports, so Node's type stripping can run them.
- Work on branch `feat/desk-room-v2`, never on `main`.

## Review Focus

- A featured flag set on more items than fit (or on none): the scene must still render, capped or empty, without crashing. → Task 2 tests.
- A featured skill whose icon is a react-icons component and not an `<img>`: the cube still gets an icon. → Task 4 test.
- Scroll progress outside 0..1 (overscroll, rubber-banding on macOS/iOS): the camera clamps and doesn't fly off. → Task 7 test.
- A user who prefers reduced motion on desktop: no tour, and the page scrolls normally into Experience. → Task 7 step.
- A missing or failed `avatar.glb` load: the hero still renders the room (Suspense fallback / error boundary, no blank canvas). → Task 8 step.
